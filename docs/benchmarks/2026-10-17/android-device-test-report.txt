应用验证

- 应用内执行 adb shell getprop ro.product.model，返回 25019PNF3C，退出码 0。
- 使用发布版同一 C MTP 桥接代码与同一 libmtp/libusb 动态库进行 1 GiB 上传、下载。
- Mac → 手机：577.268 MB/s，1.860040 秒。
- 手机 → Mac：437.716 MB/s，2.453057 秒。
- 原始文件、手机文件、下载副本 SHA-256 三者完全一致：
  bbffa35262801d058cc3d5005acd5899f4686cf75c63475832568f4239fa8472
- 这是单次短样本，不代表长时间持续吞吐；未覆盖 GUI 的每一个传输交互。

测量方法补充
- 自制小型 C 测量程序，不是 fio，也不是标准化厂商跑分工具。
- MTP 输入由 os.urandom 生成完整 1 GiB；手机内部顺序写入则循环使用 1 MiB 伪随机缓冲区，并更新首个 64 位字；两种数据模式不同。
- phone-bench.c 编译为静态 AArch64/Linux 程序；O_DSYNC 复测另加 AFT_SYNC_WRITE 宏。
- link-elf.py 用于链接这个单一无 libc 目标文件；它仅支持明确列出的重定位种类。
- 原始日志 mode 0/1/2/3 分别表示内部顺序读/顺序写/4K 随机读/4K 随机写。
- USB MTP 结果来自 mtp-test.c，使用项目 Sources/CMTP/Bridge.c 与发布版动态库。

手机内部文件系统读写（均在相同 1 GiB 测试文件内）
- 顺序读取，1 MiB 块：631.77 MB/s。
- 顺序写入，1 MiB 块，含末尾 fsync：259.45 MB/s。
- 4 KiB 随机读取，Q1T1：944.95 MB/s，230,701 IOPS；缓存影响无法排除，不视为 UFS 裸性能。
- 4 KiB 随机同步写入，Q1T1，O_DSYNC：79.29 MB/s，19,359 IOPS。
- 随机读写范围 1 GiB，随机抽样允许重复；每项最多 262,144 次操作或 30 秒。
- 均请求 O_DIRECT，并通过 fcntl(F_GETFL) 确认调用者标志保留。
- 复核前对该测试文件执行 fsync 和 POSIX_FADV_DONTNEED（返回成功）。
- Android 下载目录属于 emulated storage/FUSE 路径；调用者 O_DIRECT 并不能证明下层完全无缓存。
  AOSP 参考（内部共享存储移除下层 O_DIRECT 的实现）：
  https://android.googlesource.com/platform/packages/providers/MediaProvider/+/refs/heads/android15-platform-release/jni/FuseDaemon.cpp
- 同步写与普通缓存写不可混同比较；所有内部文件读写均不代表 USB 传输速度。

现场情况
- Google 旧版 Android File Transfer 自动启动并独占 MTP；退出其主进程后传输成功。
- libmtp 机型库将该 USB ID 标为 Xiaomi Mi-2s，实际设备由 USB/ADB 确认为 Xiaomi 15 Ultra。
- 测试后手机又变为仅 ADB 的 USB 接口配置；GUI 此时不显示 MTP 设备符合当前接口状态。
- 未执行刷机、解锁、擦除、重启、root 或全局缓存清理。
- 临时测量程序已删除，专用目录的 1 GiB 测试文件保留（内容已被内部写入测试改写）。
